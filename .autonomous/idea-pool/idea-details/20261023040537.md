## 描述

在经纬度坐标与 Geohash 字符串之间双向转换：编码时支持指定精度（1–12 位）并展示逐字符缩小的区间过程，解码时输出中心点坐标与边界框（误差范围）。Geohash 是地图 / LBS 开发中常用的地理位置编码方案（附近搜索、位置聚合），池内「地理坐标格式转换」条目是十进制 ↔ 度分秒的表示格式换算，与编码系统（base32 字符交替二分经纬度区间）是不同功能。编码与解码均为纯函数，零新依赖、纯本地。

## 设计内容（进入 Claimed 前补全）

- **工具 slug**：`geohash-codec`
- **分类 / 图标**：`ToolCategoryEnum.CRYPTO_ENCODING`（地理坐标到 base32 空间索引串的编解码，与 base32-codec / morse-codec 同属编解码族）；图标 `Binary`（体现位交织 / 区间二分）
- **查重结论**：registry 现有 `base32-codec` 等是通用字节 ↔ base32 字母表映射，不涉及经纬度区间二分与位交织；无任何地图 / 地理编码工具；池内「地理坐标格式转换（十进制 ↔ 度分秒）」（20261017220043，Pending）仅做同一点位的表示格式换算，不产出空间索引串，不构成重复；rejected.md 无同类归档。
- **文件结构**（四件套，零新依赖）：
  - `constants.ts`：`GEOHASH_ALPHABET = '0123456789bcdefghjkmnpqrstuvwxyz'`、字符→5bit 值反查表、`MIN_PRECISION = 1` / `MAX_PRECISION = 12`、`PRECISION_OPTIONS`、`ConvertModeEnum`（encode/decode）与 `MODE_OPTIONS`、`DEFAULT_SAMPLE = '57.64911,10.40744'`
  - `utils/geohash.ts`：纯函数
    - `encode(lat, lng, precision)`：偶数位二分经度、奇数位二分纬度，累积 5 bit 映射一个 base32 字符
    - `decode(hash)`：返回 `{ latitude, longitude, bbox: { minLat, maxLat, minLng, maxLng }, error: { lat, lng } }`（中心点 = 区间中点）
    - `encodeSteps(lat, lng, precision)`：逐字符返回 `{ char, bits, latRange: [lo, hi], lngRange: [lo, hi] }`，供 UI 展示区间缩小过程
    - `isValidHash(hash)` / `normalizeHash(hash)`：仅允许字母表字符，大写自动转小写
  - `index.tsx`：模式 Radio（编码 / 解码）；编码侧两个 InputNumber（纬度 -90–90、经度 -180–180）+ 精度 Select（1–12，默认 11），结果区展示 geohash 串（一键复制）与逐字符过程 Table（字符、5 bit、纬度区间、经度区间）；解码侧 Input 接受 geohash 串，输出中心点经纬度、边界框四角范围与误差；非法输入行内 Alert 且不出静默结果；载入示例 / 清空
  - `index.module.css`：container/toolbar/result/steps/hint
- **注册**：`registry.ts` 追加双语 ToolMeta（CRYPTO_ENCODING / Binary / isNew / MAINTHREAD / defaultSampleInput='57.64911,10.40744'）；`loaders.ts` 追加懒加载；FAQ 至少含「geohash 精度与误差关系」「为何相邻位置 geohash 前缀相同」「与经纬度度分秒格式转换的区别」
- **边界**：纬度限定 [-90, 90]、经度限定 [-180, 180]，越界抛错；精度限定 1–12 整数；解码字母表外字符抛错（空白先 trim、大写归一）；不做相邻 geohash（neighbors）计算
