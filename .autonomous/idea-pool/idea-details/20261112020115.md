## 描述

给定初始延迟、乘数、最大延迟、最大重试次数与抖动策略，推演每次重试的等待时间与累计耗时：支持无抖动纯指数退避（`delay = min(base * 2^n, cap)`）、全抖动（Full Jitter，AWS Architecture Blog 推荐：随机取 0–当前上限）、等抖动（Equal Jitter：固定一半 + 随机一半）三种模式，输出逐次重试时间表、期望累计耗时与抖动区间（最小/最大值），帮助开发者为 API 调用、消息消费、任务调度选择合理重试参数并避免惊群效应。现有 `cron-parser`/`cron-systemd-timer-converter` 面向定时表达式、`download-time-calculator` 面向下载耗时，均不做重试退避建模。纯本地数值计算，零依赖，S 复杂度。

## 设计内容（进入 Claimed 前补全）

- 功能范围：输入初始延迟 base、乘数 multiplier（默认 2）、最大延迟 cap、最大重试次数 maxRetries，以及抖动模式（无抖动 / Full Jitter / Equal Jitter）。
- 无抖动：`delay_n = min(base * multiplier^n, cap)`，确定性输出逐次延迟。
- Full Jitter：`delay = random(0, min(base * multiplier^n, cap))`；Equal Jitter：`delay = cap/2 + random(0, cap/2)`（cap 为当前上限）。抖动模式输出每次延迟的区间 [min, max]、期望（均值）与累计期望耗时，随机数以可注入 RNG 实现纯函数化（默认 `Math.random`，单测注入固定序列）。
- 核心交互：参数表单 + 逐次重试时间表（序号、上限、实际延迟区间、累计耗时）+ 模式说明与惊群效应提示。
- 边界：base/cap 非正数、重试次数为 0 或超上限（≤20）时给出输入校验提示；延迟统一以毫秒呈现并附带秒换算。
