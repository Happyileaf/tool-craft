## 描述

解析 Heroku / Promtail / 多数 Go 服务使用的 logfmt 行格式（`key=value` 空格分隔，值含空格时用双引号包裹并支持反斜杠转义，布尔裸值如 `key` 视为 `true`）：把单行或多行日志解析为键值表 / JSON，按行对齐展示字段；反向支持把 JSON / 键值对象序列化为合规 logfmt（自动判断何时需要加引号与转义）；对值做轻量类型推断（整数、浮点、布尔、字符串）并提供按字段筛选视图。现有 `nginx-access-log-parser`、`syslog-parser`、`apache-access-log-parser` 均为固定位置 / 正则模板的专用格式解析，`json-yaml-converter` 面向结构化文档互转，均不处理通用 key=value logfmt 语法（含引号转义状态机）。纯字符串状态机、零依赖，S–M 复杂度。

## 设计内容（进入 Claimed 前补全）

纯客户端单页工具，零网络、零新增依赖；解析与序列化收敛为可单测纯函数 `utils/logfmt.ts`（字符级状态机），UI 负责表格/JSON 视图与筛选。

- **输入**：解析方向为一行或多行 logfmt 文本；格式化方向为 JSON 对象或数组。
- **核心处理**：
  1. 状态机识别空格分隔 key=value、双引号值与反斜杠转义、裸键（视为 true）、空值与多余空白；
  2. 类型推断整数/浮点/布尔/字符串并保留原始值，超安全整数保留 string；
  3. 反向序列化自动判断加引号与转义，true 输出裸键、false 输出 key=false。
- **输出**：逐行键值表（key/原始值/推断类型）、缩进 JSON、字段名筛选、行号告警。
- **边界**：坏行按行号告警不中断；JSON 解析失败给可读错误，不抛异常。
