## 描述

在国际化域名（如 `中文.中国` / `münchen.de`）与 Punycode 编码形式（`xn--...`）之间双向转换，支持邮箱本地部分的 punycode 编码，用于排查国际化域名解析、证书与邮件问题。现有编码工具（`base64-codec`、`base32-codec`、`html-entity-codec`）均未覆盖 Punycode / IDN。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：实现 RFC 3492 Punycode 纯函数编解码，并提供域名 / 邮箱级 IDNA 转换，工具 slug 拟为 `punycode-converter`。
- **核心算法**：自实现 Bootstring（Punycode）`encode` / `decode`，零依赖；输入文本按 JS 码点（含代理对）处理。
- **域名转换**：按 `.` 拆分标签，逐标签判断——纯 ASCII 标签原样保留，含非 ASCII 标签加 `xn--` 前缀做 Punycode 编码；反向把 `xn--` 标签解码回 Unicode；支持首尾空白裁剪与大小写不敏感。
- **邮箱支持**：对 `@` 右侧域名做 IDNA 转换；左侧 local-part 原样保留（标准邮箱 local-part 不做 IDNA）。
- **核心交互**：方向切换（域名→Punycode / Punycode→域名）、输入即时转换、错误提示、复制 / 载入示例。
- **输入输出**：纯函数 `utils/punycode.ts`，不触碰 DOM / React。
- **边界情况**：空输入返回空；非法 Punycode（如 `xn--` 后无法解码、数字溢出）返回明确错误而非抛异常；已是 ASCII 的域名往返一致。
