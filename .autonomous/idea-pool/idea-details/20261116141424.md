## 描述

解析与构造 RFC 3550 定义的 RTP 报文：固定 12 字节头中的版本 V、填充 P、扩展 X、CSRC 计数 CC、标记 M、载荷类型 PT、序列号、时间戳、SSRC，以及可选的 CSRC 列表（0–15 项 ×4 字节）、头部扩展（defined by profile + 16 位长度 + 扩展数据）与填充字节。正向由字段生成 hex，反向由 hex 拆字段并逐层标注字节偏移、校验各层长度自洽性。面向 WebRTC / 音视频流媒体开发者与网络协议教学，补全工具箱在实时传输协议层的空白；纯定长位域拆包，零依赖、可固定向量验收。

## 设计内容（进入 Claimed 前补全）

**功能范围**：① 反向解析：hex 规范化后校验总长 ≥ 12；按 RFC 3550 §5.1 位布局拆 V（须为 2，否则报错）、P、X、CC、M、PT（7 位）、sequence、timestamp、SSRC；按 CC 读取 CSRC 数组；X=1 时解析扩展头（16 位 profile-specific、16 位长度（32 位字计数）、扩展数据），校验扩展声明长度与实际字节；P=1 时读取末字节填充长度并校验 1 ≤ pad ≤ 剩余长度，剥离填充后给出 payload 区间；最终输出 payload hex 与各层偏移表。② 正向构造：字段表单（V 固定 2 或允许选 0/1 用于构造畸形教学向量并告警）、CSRC 多项输入、可选扩展头与填充长度，自动计算总长并输出 hex；序列号 / 时间戳支持十进制与 hex 双输入。③ PT 标注：对静态 PT 0–34、96–127 动态范围给出文本提示（固定常量表，如 0=PCMU、8=PCMA、26=JPEG、34=H.263），不维护持续更新的载荷数据库。

**核心交互**：解析 / 构造模式切换；hex 输入框（支持空格 / 换行 / `0x`）、字段表单、分层字节偏移示意（固定头 / CSRC / 扩展 / payload / 填充五段着色）、结果字段卡片与复制按钮、RFC 3550 示例向量一键填充。

**输入输出**：输入为 hex 报文或字段集合；输出为字段表、CSRC / 扩展明细、payload 与填充 hex、各层字节偏移、长度自洽性校验结论与错误定位。

**边界情况**：不足 12 字节 → 报错；V ≠ 2 → 明确报错（构造模式除外并显式告警）；CC 声明的 CSRC 超出剩余字节 → 报错；扩展长度超出报文 → 报错；P=1 但填充长度为 0 或大于可用字节 → 报错；PT 超 0–127 → 报错；空 payload 合法（仅头部报文）；所有多字节字段按网络字节序（大端）处理。

## 验收标准（进入 Claimed 前补全，必须可验证）

- [ ] 解析标准向量：固定头 `80 60 00 01 00 00 00 0d 00 00 00 05` + payload → V=2、P=0、X=0、CC=0、M=1、PT=96、seq=1、timestamp=13、SSRC=5，payload 区间偏移 12 起
- [ ] CSRC：构造 CC=2、CSRC=[0x11223344, 0x55667788] 的报文 → 总长 20 字节，解析还原两项 CSRC，偏移表标注 12–19
- [ ] 扩展头：X=1，profile=0xBEDE、长度字=1（即 4 字节扩展数据）→ 构造后解析扩展段字节数与声明一致，payload 偏移正确后移
- [ ] 填充：P=1、末字节 pad=3 的报文 → 解析剥离 3 字节填充，payload 长度 = 总长 − 头部 − 3；pad 声明超出报文 → 报错
- [ ] 异常向量：10 字节截断、V=0、CC=5 但后续只有 8 字节、扩展长度越界 → 均返回带字节偏移的明确错误
- [ ] 正反向闭环：任意合法字段集合构造出的 hex 再解析，字段值完全一致；PT=0 / 8 / 26 显示静态载荷名提示，PT=96 标注动态范围
