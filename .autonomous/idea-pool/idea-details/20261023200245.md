## 描述

生成符合 RFC 7636 的 PKCE 参数对：随机 code_verifier（43–128 位 UNRESERVED 字符）与对应 code_challenge（默认 S256，即 BASE64URL(SHA-256(verifier)) 去除填充；可选 plain），支持一键复制与一键重新生成。OAuth 2.0 授权码 + PKCE 已是 SPA / 移动端等公共客户端的标准流程，开发者需要一对合法参数来联调授权，而手工组合现有工具极易出错：hash-generator 只输出十六进制摘要、base64-codec 不做摘要编码、strong-password-generator 只出随机串且无 unreserved 字符集与 43–128 长度区间约束。已检索确认现有已注册工具、池内活动条目与 completed / rejected 归档均无 OAuth / PKCE 方向条目。基于 WebCrypto 摘要与密码学安全随机数实现，纯函数、零新依赖、纯本地。

## 设计内容（进入 Claimed 前补全）

- **slug**：`pkce-generator`；分类 CRYPTO_ENCODING；主线程运算；图标 ShieldCheck。
- **纯函数层** `tools/pkce-generator/utils/pkce.ts`：
  - `generateVerifier(length=43)`：以 `crypto.getRandomValues` 为 CSPRNG，从 unreserved 字符表 `[A-Za-z0-9-._~]`（68 字符）经拒绝采样（拒绝 ≥204 的字节）无偏取样，长度限 43–128 整数，非法抛错。
  - `validateVerifier(verifier)`：返回 `{ valid, error }`，校验长度区间与字符集。
  - `deriveChallenge(verifier, method='S256')`：S256 时用 `crypto.subtle.digest('SHA-256', ...)` 摘要后做无填充 base64url；plain 直返 verifier；先经 validateVerifier 把关。
- **测试** `utils/pkce.test.ts`：RFC 7636 附录 B 官方向量（verifier `dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk` → challenge `E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`）、长度/字符集边界、无填充 base64url 形态（43 位、不含 `+/=`）、plain 直返、非法输入拒绝。
- **UI** `index.tsx` + `constants.ts` + `index.module.css`：打开自动生成一组参数；长度预设 43/64/96/128 + 重新生成；S256/plain 单选切换；verifier 可手动编辑并实时校验（合法/非法 Tag + 当前长度）；verifier 与 challenge 各自一键复制；非法时禁止复制并展示 Alert。
