## 描述

运维与排障时经常拿到一段 RFC 3164（BSD syslog）或 RFC 5424（结构化 syslog）原始日志，需要快速拆出时间戳、主机名、应用名/标签、进程 PID、严重级别（severity）、设施（facility）与消息正文。本工具在浏览器本地逐行解析常见 syslog 格式，输出结构化字段表格，支持 severity/facility 数值到名称（如 `16 local0`、`6 informational`）的映射、RFC 5424 的 `VERSION/HOST/APP/PROCID/MSGID/STRUCTURED-DATA/MSG` 分段，以及无法识别行的原样标记与批量解析统计。纯本地正则/字符串解析，零依赖、不上传日志（对安全敏感场景尤其重要）。现有 `nmea-parser` 面向 GPS NMEA 语句、`cookie-parser`/`url-parser` 面向 HTTP 结构；本工具面向通用 syslog 线协议，是独立的解析场景，不构成重复。

## 设计内容（进入 Claimed 前补全）

**实现载体**：`apps/web/src/tools/syslog-parser/`（`index.tsx` + `syslog.ts` 纯函数 + `__tests__/syslog.test.ts`），分类 `Network`，零依赖、零网络、主线程，日志不出浏览器。

**功能范围**：
1. 自动识别两种线协议（按行）：
   - RFC 5424：`<PRI>VERSION SP TIMESTAMP SP HOST SP APP SP PROCID SP MSGID SP STRUCTURED-DATA [SP MSG]`，PRI = facility*8+severity；TIMESTAMP 支持 NILVALUE `-` 与 RFC 3339；STRUCTURED-DATA 支持 NILVALUE 与一个或多个 `[SD-ID PARAM-PAIR...]` 块，解析为结构化数组；MSG 含 BOM(UTF-8) 时去除 BOM。
   - RFC 3164：`<PRI>TIMESTAMP HOST TAG[PID]: MSG`，TIMESTAMP 为 `Mmm dd hh:mm:ss`（无年份），TAG 为字母数字串、可选 `[pid]`、以 `:` 或 `[` 结束；同时兼容无 PRI 的纯文本行（标记为 raw/unparsed 而非报错）。
2. PRI 解码：facility（0–23，名称 kernel/user/mail/daemon/auth/.../local0–local7）与 severity（0–7，emerg/alert/crit/err/warning/notice/info/debug）数值↔名称双向映射；越界 PRI 标记错误。
3. 批量解析 textarea 多行输入：每行输出 `{ lineNo, format: 'rfc5424'|'rfc3164'|'unknown', fields, raw, errors: string[] }`；顶部统计总行数、各格式计数、错误行数；表格按字段列展示，点击行展开 SD 详情；未知行原样保留并标注。
4. 提供 2 组覆盖两种格式的示例；空行跳过不计入。

**输入输出**：输入原始日志文本；输出行结果数组与汇总统计；关键字段 `pri, facility{code,name}, severity{code,name}, timestamp, host, app, procid, msgid, structuredData, message`。

**边界情况**：空输入/空行、PRI 缺失或非数字、PRI 越界（>191）、5424 字段数不足、SD 括号不配对、NILVALUE `-`、无年份 3164 时间戳、TAG 无 PID、无 PRI 纯文本行、BOM 处理、单行超长不卡死（正则无回溯炸弹）。
