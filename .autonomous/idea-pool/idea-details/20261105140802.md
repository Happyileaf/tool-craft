## 描述

依据 Fetch 标准（W3C/WHATWG CORS 协议）在浏览器本地生成跨域共享响应头配置：用户以表单选择允许的来源模式（单 Origin、白名单多 Origin 回显、通配 `*`）、是否允许凭证（`Access-Control-Allow-Credentials: true`，并对「通配符 + 凭证」这一非法组合给出明确错误，因为凭证模式下不允许 `*`）、允许方法、允许请求头、暴露头（`Access-Control-Expose-Headers`）、预检缓存时间 `Access-Control-Max-Age` 与 `Vary: Origin` 提示；输出 Nginx、Apache .htaccess、IIS web.config 与通用 HTTP 头四种格式片段，并提供反向解析模式：粘贴现有响应头后逐条校验语法与组合合法性（如 `Allow-Headers: *` 在凭证请求中的限制、方法名大小写、头名字符集、Max-Age 非负整数）。

池中已有 `security-headers-generator`（CSP/HSTS/X-Frame-Options 等安全响应头）与 `csp-builder`，但 CORS 是独立的跨域协议族，头字段语义、预检（OPTIONS）流程与凭证组合规则均不同于 CSP；经全仓检索无 `Access-Control-*` 相关工具，不构成重复。配置生成与校验均为确定性字符串处理，固定表单输入可断言四种格式的完整输出，零依赖本地运行，复杂度 S。参考来源：MDN「Cross-Origin Resource Sharing (CORS)」与 Fetch Standard §3.2 HTTP-header 处理。

## 设计内容（进入 Claimed 前补全）

纯客户端单页工具，零网络、零新增依赖；CORS 规则收敛为可单测纯函数 `utils/cors.ts`，UI 负责表单配置、规则告警与响应头/nginx 片段渲染。

- **输入**：来源策略（通配 `*` / 反射 Origin / 白名单多来源）、是否允许凭证、允许方法集合、允许请求头、预检缓存秒数、暴露头。
- **核心处理**：① 按 Fetch 标准生成 `Access-Control-Allow-Origin`、`Allow-Credentials`、`Expose-Headers`、`Max-Age` 等实际响应头与 `Allow-Methods/Allow-Headers` 预检头；② 拦截「凭证 + 通配来源」「凭证 + 通配头/方法」等非法组合并报错；③ 反射模式强制补 `Vary: Origin`；④ 同步生成可直接粘贴的 nginx `add_header` 片段。
- **输出**：分组展示的响应头键值、预检头、nginx 配置片段与规则告警/错误列表。
- **边界**：空来源、非法 Origin 语法、白名单为空时明确报错；不生成通配凭证这种浏览器会拒绝的无效配置。
