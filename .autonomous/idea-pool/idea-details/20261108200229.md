# Bloom Filter 交互式模拟器（多哈希策略 / 假阳性率可视化）

- **Idea ID**：20261108200229
- **类型**：Web Tool
- **来源**：Existing Gap
- **类别**：Text/Data

## 问题陈述

布隆过滤器（Bloom Filter）是工程中高频出现的概率型数据结构——缓存穿透防护、爬虫 URL 去重、黑名单快速判否、分布式 KV 的 SSTable 索引等场景都依赖它。开发者在选型时需要回答三个关键问题：给定预期元素量 n 和可接受假阳性率 p，位数组长度 m 与哈希函数个数 k 应如何取？实际填充后假阳性率如何随负载变化？为什么"不存在"判定一定可靠而"存在"判定可能误报？

Tool-Craft 现有 303 个工具中没有任何概率数据结构相关工具：`bitmask-calculator` 只处理静态位掩码与 popcount（Hamming weight），`hash-playground` 只输出单次哈希摘要，`uuid-generator` 等只负责生成。活动池、completed.md、rejected.md 中经全文检索（Bloom / 布隆）均无相同或高度相似 Idea。

## 方案概述

构建一个纯前端、零依赖的 Bloom Filter 交互式模拟器，核心能力：

1. **参数规划器**：输入预期元素数 n 与目标假阳性率 p，按标准公式输出推荐位数组大小 m（`m = -n·ln(p) / ln(2)²`，向上取整为 8 的倍数）、最优哈希数 k（`k = (m/n)·ln2`，四舍五入）、理论占用字节数。
2. **交互式过滤器**：用户批量粘贴元素（每行一个）执行 add，再输入任意元素执行 membership 查询；底层用 `Uint8Array` 位数组 + k 个双哈希派生槽位（Kirsch–Mitzenmacher 技巧：`h_i(x) = h1(x) + i·h2(x) mod m`，仅需 FNV-1a 两个种子，无需引入哈希库）。
3. **状态可视化**：位图按字节渲染为 0/1 方格（已置位高亮），实时展示已填充位数、实际负载率 m_used/m、当前实测/理论假阳性率 `(1 - e^(-kn/m))^k`；查询命中时高亮参与判定的 k 个槽位，直观区分"确定不存在（有 0 槽位）"与"可能存在（全 1）"。
4. **对照实验**：支持同时给出两个不同参数（如 k=1 与最优 k）的过滤器，对同一批查询统计假阳性次数，演示 k 过大/过小的退化。

## 价值假设

- **高频教学价值**：数据结构 / 系统设计面试与计算机专业课程的标准知识点，"假阳性率随负载曲线"的可视化能把概率公式变成可交互的直觉。
- **真实工程诉求**：后端选型时可直接用参数规划器确定 Redis Bloom / Guava `BloomFilter` 的容量与误差参数，避免凭感觉取值。
- **与现有工具互补**：补齐 Tool-Craft 在概率数据结构方向的空白，与 `bitmask-calculator`（确定性位运算）、`hash-playground`（单值摘要）边界清晰不重叠。

## 目标用户

- 准备系统设计 / 数据结构面试的开发者与计算机专业学生；
- 需要为缓存穿透防护、URL 去重、黑名单等场景确定 Bloom Filter 参数的后端工程师；
- 想直观理解概率型数据结构误差来源的自学者。

## 核心功能（MVP）

1. 参数规划表单：n、p 输入 → m、k、字节占用、理论 FPR 输出；
2. 批量 add（文本域每行一个元素）+ 单元素 membership 查询，结果区分"确定不存在 / 可能存在"；
3. 位图方格可视化 + 参与判定槽位高亮 + 实时负载率与理论 FPR；
4. 双过滤器对照模式，同批查询统计实测假阳性次数。

## 不做什么（边界）

- 不实现 Counting Bloom / Cuckoo Filter / Scalable Bloom 等变体（保持 S–M 范围）；
- 不做持久化、跨页面同步或服务端存储（纯浏览器内存态）；
- 不接入加密级哈希函数（FNV-1a 派生仅用于模拟演示，明确标注非加密用途）；
- 不处理超大容量（位数组上限按浏览器内存限制在约 1000 万 bit 并给出提示）。

## 技术可行性

- 位存储用原生 `Uint8Array`，双哈希用约 20 行 FNV-1a 实现，Kirsch–Mitzenmacher 派生 k 个槽位，零运行时依赖；
- 全部为输入→状态→输出的纯函数（`planParams(n, p)`、`add(bits, x)`、`query(bits, x)`、`theoreticalFpr(n, m, k)`），可完整单测；
- 位图渲染为 CSS Grid 方格，10 万 bit 量级内无性能压力；
- 复杂度评估：**M**（参数公式 + 哈希派生 + 可视化与对照统计），符合 tool-development SOP 的 S–M 要求，主线程即可承载。

## 验收标准

1. 给定 n=10000、p=0.01，输出 m≈95851（12KB）、k=7，与 Guava/教科书公式结果一致（误差 <1%）；
2. add 一个未出现过的元素必返回"确定不存在"（零假阴性，1000 次随机抽样验证）；
3. 满负载后对随机不存在元素批量查询，实测 FPR 与理论值偏差在合理抽样误差内（±20%）；
4. 对照模式下 k=1 与最优 k 的实测假阳性次数差异方向与理论一致；
5. 纯函数模块（规划 / add / query / FPR）单测覆盖率 ≥90%，全程零网络请求、零新依赖。

## 风险与约束

- 超大 n 时位图渲染节点过多：按字节聚合渲染 + 虚拟化或仅渲染前 N 字节并提示；
- FNV-1a 分布质量弱于 MurmurHash：仅用于教学模拟，文档明确标注，规划公式不受影响；
- 实测 FPR 需要足够查询样本：内置一键生成随机不存在样本（基于 `crypto.getRandomValues`，与 `secure-random-picker` 同源思路）。
