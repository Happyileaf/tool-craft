## 描述

根据 WWW-Authenticate challenge（realm、nonce、qop、opaque、algorithm 等）与用户名/密码/请求方法/URI，按 RFC 2617（MD5）与 RFC 7616（SHA-256 等、userhash）逐步计算 A1、A2、response 摘要，展示 HA1/HA2 中间值，并生成可直接放入 Authorization 请求头的完整字符串；支持 qop=auth 与 auth-int（实体体哈希）及 nonce count / cnonce。MD5/SHA 哈希本地已有纯实现，可复用，零新增依赖，全部在浏览器内完成、不外传凭据。

## 设计内容（进入 Claimed 前补全）

- 功能范围：输入用户名、密码、realm、nonce、method、uri，选择 algorithm（MD5 / MD5-sess / SHA-256 / SHA-256-sess）与 qop（无 / auth / auth-int），填写 cnonce、nc、opaque；auth-int 时提供实体体文本并计算其哈希。实时输出 HA1、HA2、response 与完整 `Authorization: Digest ...` 请求头。
- 核心交互：凭据与 challenge 字段变更即时重算；支持自动生成 8 位十六进制 nc 与随机 cnonce；SHA-256 算法下可开启 userhash 将用户名替换为 `H(username:realm)`；每个计算步骤以只读区块展示，便于对照 RFC 排查；密码默认掩码显示并可切换。
- 输入输出：输入为 challenge 参数与凭据，输出为中间摘要、最终 response 值及可直接复制的 Authorization 头；计算细节在浏览器本地完成，不上传任何凭据。
- 边界情况：MD5-sess 的 HA1 需再次混入 nonce 与 cnonce；qop=auth-int 的 A2 需拼接实体体哈希；开启 qop 时 nc 必须为 8 位十六进制且 cnonce 必填，否则给出明确校验错误；无 qop 时不输出 nc/cnonce 字段。
