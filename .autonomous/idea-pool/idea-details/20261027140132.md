## 描述

实现 Bech32 与 Bech32m 编码（BIP-173 / BIP-350）：支持任意 HRP（human-readable part）+ 数据字节的编码与解码，自动选择并标注 Bech32（版本 0，如原生隔离见证地址）或 Bech32m（版本 1+，如 Taproot）校验和常量，提供校验和验证与错误定位，并内置 SegWit 地址（P2WPKH / P2WSH / P2TR）的识别与 script program 解读。与已有 `base58-codec` 不同：后者只做 Base58 / Base58Check，不含 Bech32 polymod 校验与 HRP 分离逻辑；本工具补齐现代比特币地址与其它 Bech32 数据编码场景，全部本地运算。

## 设计内容（进入 Claimed 前补全）

工具 slug：`bech32-codec`，单页双向：

1. 编码区：HRP 输入（如 `bc`）+ 数据输入（hex 字节串，如 witness program）+ 编码类型选择（Bech32 常量 1 / Bech32m 常量 0x2bc830a3 / 自动：SegWit 版本 0 用 Bech32、版本 1+ 用 Bech32m），输出完整 bech32 字符串。
2. 解码区：粘贴 bech32 字符串，先校验整体大小写（不允许混用）、字符集（charset `qpzry9x8gf2tvdw0s3jn54khce6mua7l`）、长度（≤90，按 BIP-173 规则），分离 HRP 与 data，polymod 校验：分别按 Bech32 / Bech32m 常量验证，明确报出「校验和有效（类型）」或「两种常量均不匹配」。
3. SegWit 解读：HRP 为已知主网/测试网前缀且 data 首字节 witness version ∈ 0–16、program 长度合法（v0：20/32；v1：可含 32 等）时，标注 P2WPKH / P2WSH / P2TR（其他长度显示 witness program hex 与版本，不武断命名）。
4. 5–8 bit 转换用标准 convertbits（带 padding 严格校验）。

核心纯函数放 `utils/bech32.ts`（polymod / hrpExpand / createChecksum / verifyChecksum / encode / decode / convertbits / segwit 解读），以 BIP-173、BIP-350 官方 VALID/INVALID 向量做 Vitest；零依赖。
