## 描述

面向嵌入式 / 单片机 / LCD 驱动开发场景，在 24 位 RGB888（`#RRGGBB`）与 16 位帧缓冲像素格式之间双向转换：支持 **RGB565**（红 5 位 / 绿 6 位 / 蓝 5 位，ST7735/ILI9341 等常见 TFT 屏使用）与 **RGB555 / RGB1555**（各 5 位，最高位未用或作 a 位）两种布局，输出大端 / 小端两种字节序（`0xF800`、`0x00F8` 等）以及 C 语言十六进制字面量与高低字节拆分（`HIGH_BYTE` / `LOW_BYTE`），并支持批量粘贴（每行一个颜色）一次转换一列；反向支持把 16 位值还原成最接近的 RGB888（低位补 1 扩展以减小量化误差，符合常见 SDK 做法）并显示量化前后色差。典型场景：写屏幕取模代码、对着调试器里的像素值反查颜色、UI 配色表落地。纯本地位运算、确定性输出、零依赖，可用固定向量验收。已实现的 color-palette / oklch-workbench / color-mixer / color-harmony / dark-mode-converter / color-naming-token / css-unit-converter 等颜色工具全部面向设计与 CSS，在池 Idea 中亦无任何嵌入式像素格式条目，不构成重复。

- **文件结构**（三件套，零新依赖）：
  - `constants.ts`：`PixelFormatEnum`（rgb565/rgb555）、`FORMAT_OPTIONS`、`EndianEnum`（big/little）、`ENDIAN_OPTIONS`、`ConvertModeEnum`（encode 正向 hex→16 位 / decode 反向 16 位→hex）、`MODE_OPTIONS`、`DEFAULT_BATCH = '#FFFFFF\n#000000\n#FF0000\n#00FF00\n#0000FF'`
  - `utils/rgb565.ts`：纯函数
    - `parseHexColor(input)`：接受 `#RRGGBB` / `RRGGBB`（大小写不敏感），返回 `{ r, g, b }`，非法抛错
    - `rgbToPixel(r, g, b, format)`：565 为 `((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)`；555 为 `((r & 0xF8) << 7) | ((g & 0xF8) << 2) | (b >> 3)`
    - `pixelToBytes(value, endian)`：大端 `[v >> 8, v & 0xFF]`，小端逆序
    - `pixelToRgb(value, format)`：取出各通道位域后低位补 1 扩展（5 位 `(x << 3) | 0x07`、6 位 `(x << 2) | 0x03`），555 位域为 `>>10 / >>5 / &0x1F`
    - `colorDistance(a, b)`：RGB 欧氏距离，用于量化色差展示
    - `toHexLiteral(value)` / `toHexColor(r,g,b)`：`0xFFFF` / `#RRGGBB` 格式化
    - `convertBatch(lines, ...)`：按行转换，空行跳过，返回每行 `{ source, ok, value?, bytes?, error? }`
  - `index.tsx`：模式 Radio（正向批量 / 反向批量）、像素格式 Radio（RGB565/RGB555）、字节序 Radio（大端/小端）、输入 TextArea（每行一个值，反向接受 `0xF800` / `F800`）、结果以只读 TextArea + antd Table 双视图呈现：16 位 C 字面量、HIGH/LOW 字节、选定字节序字节对；反向行附色块预览与色差 Δ；错误行内联提示且不影响其他行；载入示例 / 清空 / 复制结果
  - `index.module.css`：container/toolbar/label/swatch/hint
- **注册**：`registry.ts` 追加双语 ToolMeta（DESIGN_COLOR / BgColorsOutlined / isNew / MAINTHREAD / defaultSampleInput='#3B82F6'）；`loaders.ts` 追加懒加载条目；FAQ 至少含「RGB565 与 RGB555 位布局区别」「大小端如何选」「反向还原为何与原色有差异（量化）」
- **边界**：仅支持 `#RRGGBB` 六位十六进制（不支持 3 位简写 / alpha）；16 位值限定 0x0000–0xFFFF，越界报错；批量空行跳过、trim 后解析，输出行数 = 有效输入行数；每行独立报错不阻塞整批；不做抖动（dithering）

## 验收标准（进入 Claimed 前补全，必须可验证）

- [ ] RGB565 固定向量：`#FFFFFF`→`0xFFFF`、`#000000`→`0x0000`、`#FF0000`→`0xF800`、`#00FF00`→`0x07E0`、`#0000FF`→`0x001F`
- [ ] RGB555 固定向量：`#FFFFFF`→`0x7FFF`、`#FF0000`→`0x7C00`、`#00FF00`→`0x03E0`、`#0000FF`→`0x001F`、黑→`0x0000`
- [ ] 字节序：`0xF800` 大端字节为 `F8 00`，小端为 `00 F8`；HIGH_BYTE/LOW_BYTE 拆分正确
- [ ] 反向：`0xF800`（565）经低位补 1 扩展还原为 `r=0xFF` 原色近似值并给出与 `#FF0000` 的非负色差；`0x07E0` 还原绿色通道；正向→反向往返对任意输入不报错
- [ ] 批量模式：5 行示例输入输出 5 行结果且顺序一致；空行跳过；单行非法（如 `#GG0011`、`0x10000`）仅该行报错
- [ ] 输入兼容：hex 允许有无 `#`、大小写不敏感；16 位值允许 `0x` 前缀有无
- [ ] `pnpm lint && pnpm typecheck && pnpm test && pnpm build` 全部通过；工具页可通过 /tools/rgb565-converter 访问
