## 描述

针对 HTTP `Link` 响应头（如 `Link: <https://a.test/next>; rel="next"; hreflang=en, </feed>; rel="alternate"; type="application/atom+xml"`）做解析与构造：按 RFC 8288 把一个或多个逗号分隔的 link-value 拆成结构化条目，提取每个 URI-Reference 及其参数（`rel`/`rev` 关系类型集合、`anchor`、`hreflang`、`type`、`media`、`title`/`title*`、扩展参数），处理引号字符串内的逗号 / 分号（避免误切分），并对相对 URI-Reference 结合可选 anchor/base 做归一；反向支持由结构化条目数组构造合规 Link 头。开发者在处理分页（`rel=next/prev`）、WebFinger、HATEOAS、预连接（`rel=preload/preconnect`）时常需核对复杂 Link 头，现有 `url-parser` 只解析单个 URL、`http-headers-reference` 仅为字段文档，均不能解析 link-value 列表语法。纯本地确定性计算、零新增依赖。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：实现 RFC 8288 Link 头字段的解析与构造，工具 slug 拟为 `link-header-codec`。
- **核心算法**：
  - 词法切分：在尊重尖括号 `<...>` 与引号字符串 `"..."` 的前提下，按顶层逗号拆分多个 link-value、按分号拆分参数，正确转义引号内特殊字符。
  - 结构化：每条输出 `{ uriReference, rel: string[], anchor?, hreflang?, type?, media?, title?, extParams }`；`rel` 按空白拆为关系类型集合并小写归一。
  - 相对归一（可选）：提供 base/anchor 输入时，对相对 URI-Reference 按 RFC 3986 解析为绝对 URI（可复用相对引用解析能力，仅作展示归一）。
  - 构造：由条目数组反向生成符合 ABNF 的 Link 头，参数值按需加引号。
- **核心交互**：上半区头值输入 + 可选 base、条目表格（URI、rel 标签、其余参数）、方向切换到构造、复制 / 载入分页与预连接示例。
- **输入输出**：纯函数 `utils/linkHeader.ts`，不触碰 DOM / React。
- **边界情况**：空输入返回空数组；缺尖括号、空 URI、未闭合引号、非法参数等返回明确错误而非抛异常；仅做语法解析与归一，不发起网络请求、不校验 rel 是否为注册表关系；不持久化输入。

## 验收标准

- [ ] 正确解析含两个条目的示例头：第一条 URI `https://a.test/next` 且 `rel=["next"]`、`hreflang="en"`；第二条 `/feed` 且 `rel=["alternate"]`、`type="application/atom+xml"`，逗号 / 分号在引号内不被误切分。
- [ ] `rel` 多值（`rel="next preload"`）正确拆为集合并小写归一；相对 URI-Reference 在提供 base 时归一为绝对 URI，未提供时原样保留。
- [ ] 构造方向：由结构化条目生成的 Link 头可被本解析器往返还原（URI 与参数一致）；缺尖括号、未闭合引号、空 URI 等畸形输入返回可读错误而不抛异常。
- [ ] 核心逻辑为纯函数并配单元测试，纯本地计算、零新增依赖、主线程即时完成。
