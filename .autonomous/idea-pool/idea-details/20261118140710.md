## 描述

后端 API 返回结构化错误时，RFC 7807（Problem Details for HTTP APIs）规定了 `application/problem+json` 媒体类型与 `type` / `title` / `status` / `detail` / `instance` 五个标准成员，并允许扩展自定义成员；开发者手工拼装时容易出现 status 与 HTTP 状态码不一致、URI 字段非法、扩展成员与标准成员冲突等问题，且联调时缺少反向校验工具。本工具提供双向能力：① 生成模式——表单输入标准成员（含 status 码与自动匹配的标准原因短语）、任意自定义扩展成员（扁平 key-value，校验 key 不与保留成员重名），输出规范化 JSON（含可复制的响应头 `Content-Type: application/problem+json`）与等价的 `application/problem+xml` 参考输出；② 解析模式——粘贴已有 Problem JSON，逐字段校验 type/instance 的 URI 合法性、status 是否为有效 HTTP 状态码（100–599）且与 title 原因短语是否匹配、成员类型是否符合 RFC，并高亮问题字段。现有 HTTP 类工具覆盖状态码速查（http-status-codes）、报文解析（http-message-parser）、安全头/CORS/Cache-Control 等头部生成，但均不涉及 RFC 7807 错误体结构；与 cookie-parser、content-disposition-codec 等同属「HTTP 生态小构件」但协议域独立。四源查重全文检索「Problem Details / RFC 7807 / problem+json」在活动池、completed.md、rejected.md 与已注册工具中零命中；全部为本地 JSON 拼装与规则校验，零新依赖、纯函数可测，符合红线。

## 设计内容（进入 Claimed 前补全）

**功能范围**：① 生成模式（RFC 7807）——表单维护 `type`（默认 `about:blank`）、`title`、`status`、`detail`、`instance` 五个标准成员：status 限定 100–599 三位 HTTP 码，title 留空时按状态码自动推导标准原因短语（显式 title 优先保留）；自定义扩展成员为扁平 key-value，值经 JSON 还原真实类型，并拦截与五个标准字段重名的冲突键及非法键名。输出规范化 JSON 与可复制的 `Content-Type: application/problem+json` 响应头。② 解析模式——粘贴已有 Problem JSON，拆分为标准字段与扩展字段两组展示，校验 type/instance 的 URI 引用合法性、status 有效性，并对缺 status、`about:blank` 下 title 与状态短语不一致等情形输出合规告警。

**核心交互**：生成/解析双 Tab；标准成员表单 + 扩展成员动态增删行；JSON 输出区带复制按钮；解析区分组表格 + Alert 告警；内置 403 余额不足示例一键填充。

**输入输出**：输入为表单字段、扩展键值对或待解析 JSON 文本；输出为 Problem 文档对象、序列化 JSON、响应头字符串、解析分组与告警/错误列表。

**边界情况**：非 100–593 三位码、非数字 status 拒绝；非法 URI 引用拒绝；扩展键与标准字段冲突或键名非法 → 拒绝并定位键名；畸形 JSON、非对象根、非法 status 的粘贴文本 → 明确报错；生成文档经解析往返零漂移；标准字段名集合固定为五个且对外导出供校验复用。
