## 描述

网络运维与排障中常需判断设备在收到 ARP 请求时是否应触发 Proxy ARP（跨子网代答，RFC 1027）或 Local Proxy ARP（同子网但二层隔离时代答），并构造对应的应答报文。本工具：① 输入 ARP 请求的发送者 IP/MAC、目标 IP 与接收接口的 IP/掩码、接口 Proxy ARP / Local Proxy ARP 开关状态，逐步演示判定逻辑（目标是否本子网、是否开启对应代答、是否禁止代答自身等边界），输出「代答 / 不应答」结论与原因；② 代答模式下构造以太网 ARP Reply 帧（opcode=2，Sender MAC 为接收接口 MAC、Sender IP 为被请求目标 IP），输出十六进制字节布局与字段对照，并与普通 ARP 应答逐字段高亮差异。现有 arp-packet-codec 只做 RFC 826 普通 ARP 报文的解析与构造，不包含任何代答判定逻辑；四源查重全文检索「Proxy ARP / 代理 ARP / Local Proxy ARP / RFC 1027」在活动池、completed.md、rejected.md 与已注册工具中零命中。纯本地规则判定与字节拼装、零新依赖、固定报文向量可验收，符合红线。
