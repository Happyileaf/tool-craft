## 描述

在 UDP 8 字节首部字段（源端口 / 目的端口 / 长度 / 校验和）与十六进制报文之间双向转换：正向按字段构造首部并拼接 payload 输出 hex 流，可选基于 IPv4 / IPv6 伪首部计算校验和并回填；反向粘贴 hex（或带空格 / `0x` 前缀的报文转储）解析出各字段、校验长度一致性并验证校验和。面向网络协议学习、抓包对照与嵌入式 UDP 栈调试场景，与现有 `tcp-segment-codec`（TCP 报文）、`ipv4-header-parser`（IP 层）、`arp-packet-codec` 形成协议编解码工具链；纯本地位运算与反码求和，零依赖。

## 设计内容（进入 Claimed 前补全）

**功能范围**：① 正向构造：输入源端口（0–65535，允许 0 表示未指定）、目的端口（1–65535）、payload（文本或 hex），自动计算 Length = 8 + payload 字节数；校验和支持三种模式：禁用（填 0x0000，IPv4 合法）、自动计算（IPv4 伪首部：源/目的 IP、零、协议号 17、UDP 长度）、IPv6 伪首部（协议号 17，伪首部长度字段为 UDP 长度）；输出完整 hex 与分行字节视图。② 反向解析：hex 输入规范化（去空格 / 换行 / `0x`），不足 8 字节报错；拆出四字段，校验 Length 与实际字节数是否一致；校验和为 0 时标注「IPv4 未启用」，非 0 时按用户提供的伪首部地址重算并给出 通过 / 不通过。③ 奇数长度 payload 补 0 字节参与校验和（不写入报文）；校验和求和结果为 0xFFFF 时按 RFC 768 处理（取反后为 0 时改写为 0xFFFF 传输）。

**核心交互**：构造 / 解析模式切换；端口与 payload 输入、IP 版本与伪首部地址输入、校验和模式单选；hex 输出区带复制按钮与按字节分行视图；解析结果字段卡片 + 校验和状态徽标；内置 RFC 768 示例向量一键填充。

**输入输出**：输入为端口号、payload、伪首部 IP 与模式，或 hex 报文；输出为 hex 字节流、字段表、长度与校验和校验结论、错误定位（字节偏移）。

**边界情况**：端口超出 0–65535 → 报错；hex 含非十六进制字符或奇数个 nibble → 报错；Length < 8 或与实际不符 → 明确报错；目的端口为 0 → 报错；payload 为空时 Length = 8 且允许计算校验和；IPv6 不允许校验和为 0（RFC 8200 强制）→ 模式为禁用且选 IPv6 时报错；伪首部地址缺失时只构造不验证并提示。
