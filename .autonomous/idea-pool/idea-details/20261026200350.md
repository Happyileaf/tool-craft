## 描述

粘贴一段原始 HTTP 报文（抓包 / `openssl s_client` / `nc` / 浏览器 Copy as cURL 之外的裸报文），自动识别是请求还是响应并结构化解析：请求侧解析 method、path（含 query string 拆分）、HTTP 版本、逐行 headers（含折叠续行与重复头处理）、body；响应侧解析 HTTP 版本、状态码与原因短语（状态码自动关联含义说明，可复用 HTTP 状态码速查的数据）、headers、body。对常见 header 做人类可读展开：`Content-Type`（含 charset/boundary）、`Content-Length`、`Set-Cookie` / `Cookie`（属性拆分）、`Cache-Control` 指令、`Authorization` 方案识别（Bearer/Basic 并对 Basic 做 Base64 解码预览，敏感场景给出提示）、`Transfer-Encoding: chunked` 指示 body 为分块编码；同时检测报文异常（路径含非法空格、header 缺冒号、Content-Length 与实际 body 长度不一致、裸 `\n` 行分隔）。典型场景：调试网关 / 反向代理、读 WAF 拦截日志、学习 HTTP 协议。纯本地文本解析、确定性输出、零依赖、不上传任何报文，可用固定向量验收（一段标准 GET 请求、一段 200 JSON 响应、Set-Cookie 多属性、chunked body、Basic 认证解码、三类畸形报文的报错定位）。与已实现工具的边界：`curl-to-code` 解析的是 cURL 命令字符串并生成代码、`url-parser` 只处理 URL、jwt-parser 只处理 JWT；在池「Cookie 字符串解析与生成器」仅处理 Cookie 头本身，「HTTP 状态码速查」仅查状态码表——本工具面向完整 raw message 的解析，是上述能力的上游整合而非子集，不构成重复。
