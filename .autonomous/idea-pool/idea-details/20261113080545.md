## 描述

按 RFC 3986 §5「Reference Resolution」把一个相对引用（relative-ref，如 `../b/c/./d`、`//host/x`、`?q=1`、`#frag`）结合基础 URL（base URI）解析为绝对目标 URL，并逐步展示合并过程（scheme/host 继承判断、相对路径拼接、`remove_dot_segments` 点段归一化、query/fragment 覆盖规则）。现有 `url-parser` 仅对单个完整 URL 做结构化拆解（scheme/host/path/query/hash），不接受「base + 相对引用」两个输入、也不演示 §5.2–§5.3 的分步合并与点段移除；开发者在处理 HTML `<base>`、HTTP `Location` 相对跳转、爬虫链接归一化时缺乏可解释的教学/排错工具。纯本地确定性算法、零新增依赖，可用 RFC 3986 官方案例（§5.4.1/§5.4.2）做固定验收。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：实现 RFC 3986 §5 的完整引用解析流程，工具 slug 拟为 `relative-url-resolver`。
- **核心算法**：
  - `parseReference`：按 §5.2.2 判定相对引用是否为 network-path（`//` 开头）、absolute-path（`/` 开头）、relative-path 或空引用，决定继承 base 的哪些组件。
  - `merge`：按 §5.3 合并 base 与引用的 scheme、authority、path、query、fragment。
  - `removeDotSegments`：严格按 §5.2.4 输入缓冲 / 输出栈算法处理 `.` 与 `..` 段，输出归一化路径。
- **分步可视化**：展示输入组件、合并判定（继承 vs 覆盖）、点段移除前后路径、最终目标 URL，便于教学核对。
- **核心交互**：两个输入框（Base URL、Relative Reference）、即时解析、错误提示（非法 base、畸形引用）、复制结果 / 载入 RFC 官方案例。
- **输入输出**：纯函数 `utils/resolve.ts`，不依赖浏览器 `new URL`（自实现以保证跨环境一致且可解释），不触碰 DOM / React。
- **边界情况**：空引用返回 base 去掉 fragment 后的目标；仅 `#frag` / 仅 `?q` 的覆盖；根路径与 authority 缺省；非法百分号编码、非法 host 给出明确错误而非抛异常；不做网络请求、不持久化输入。

## 验收标准

- [ ] 通过 RFC 3986 §5.4.1「正常示例」全部固定向量，例如 base `http://a/b/c/d;p?q` 下：`g` → `http://a/b/c/g`、`/g` → `http://a/g`、`g?y` → `http://a/b/c/g?y`、`//g` → `http://g`。
- [ ] 通过 §5.4.2「异常示例」关键向量：`../../../g` → `http://a/g`、`/./g` → `http://a/g`、`g/./h` → `http://a/b/c/g/h`、`g/../h` → `http://a/b/c/h`，点段归一化与 RFC 输出逐字符一致。
- [ ] 空引用、纯 fragment、纯 query、network-path 引用的组件继承 / 覆盖规则正确；非法 base 或畸形引用返回可读错误而不抛异常。
- [ ] 核心逻辑为纯函数并配单元测试，纯本地计算、零新增依赖、主线程即时完成，且不调用 `new URL` 以保证结果可解释、跨环境一致。
