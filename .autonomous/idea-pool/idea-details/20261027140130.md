## 描述

对任意文本应用 Unicode 四种标准规范化形式（NFC / NFD / NFKC / NFKD）转换，展示转换前后字符串、字节长度变化、逐码点（code point）差异，并可一键复制结果。用于排查「看起来相同但字节不同」的字符串比较问题、组合字符与预组合字符（如 é 的 U+00E9 与 U+0065+U+0301）归一化、全角兼容字符处理与安全场景下的输入归一化。与已有 `fullwidth-halfwidth-converter` 不同：后者仅对 ASCII 可打印字符按码位 ±0xFEE0 做硬偏移，不调用 `String.prototype.normalize`，也不覆盖半角片假名、兼容字符与组合标记，本工具提供标准四形式的通用规范化。

## 设计内容（进入 Claimed 前补全）

- **工具 slug**：`unicode-normalization`
- **分类 / 图标**：`ToolCategoryEnum.TEXT_CONTENT`（文本归一化与码点分析）；图标 `Type`
- **查重结论**：`fullwidth-halfwidth-converter` 仅做 ASCII ±0xFEE0 硬偏移、不调用 normalize、不覆盖组合标记 / 兼容字符 / 半角片假名；其余文本工具（text-case-converter / line-ending-converter / string-escape / text-entropy-calculator）均不做 Unicode normalization form 转换；rejected.md 无同类归档，池内无同类条目。
- **文件结构**（四件套，零新依赖）：
  - `constants.ts`：`NormalizationFormEnum`（NFC/NFD/NFKC/NFKD）、`FORM_OPTIONS`（含中英文名与一句话说明，如「规范合成 / 规范分解 / 兼容合成 / 兼容分解」）、`DEFAULT_FORM = 'NFC'`、`DEFAULT_SAMPLE`（含预组合 é、分解序列、全角字符与序号 ① 等典型字符）
  - `utils/normalize.ts`：纯函数
    - `normalizeText(text, form)`：直接调用 `String.prototype.normalize(form)`
    - `toCodePoints(text)`：按码点迭代（正确处理代理对），返回 `{ codePoint, hex: 'U+XXXX', char }[]`
    - `measureText(text)`：码点数、UTF-16 码元数（`length`）、UTF-8 字节数（`TextEncoder`）
    - `diffCodePoints(before, after)`：对码点序列做 LCS 对齐，输出 `{ type: 'equal' | 'removed' | 'added', ... }[]`，用于逐码点高亮差异
  - `index.tsx`：形式 Radio（NFC/NFD/NFKC/NFKD）、输入 TextArea、结果只读 TextArea + 复制；指标行展示转换前后码点数 / UTF-16 码元 / UTF-8 字节与「是否与原文序列一致」；码点差异以彩色 Tag 序列呈现（绿=不变、红=删除、蓝=新增），组合标记与代理对不拆坏；载入示例 / 清空
  - `index.module.css`：container/toolbar/metrics/codepoints/tag 等
- **注册**：`registry.ts` 追加双语 ToolMeta（TEXT_CONTENT / Type / isNew / MAINTHREAD / defaultSampleInput 为含 é / ① / 全角字符的样例）；`loaders.ts` 追加懒加载；FAQ 至少含「NFC 与 NFD 的区别」「NFKC 为何会改变字符（兼容性分解）」「emoji ZWJ 序列会受影响吗」
- **边界**：空输入输出空结果不报错；不维护 Unicode 字符名称表（码点以 U+XXXX 展示）；表单中文本可含不完整代理序列时按浏览器 String API 行为透传，不做抛错
