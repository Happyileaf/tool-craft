# LRU / LFU 缓存淘汰策略模拟器（命中率对比与淘汰过程回放）

- **Idea ID**：20261108200231
- **类型**：Web Tool
- **来源**：Existing Gap
- **类别**：Developer Tool

## 问题陈述

缓存淘汰策略是后端面试与系统设计的高频考点，也是真实工程中影响命中率的关键决策。LRU（最近最少使用）与 LFU（最不经常使用）的行为差异、LFU 的历史计数污染问题、容量与命中率的关系，仅靠看代码或纸面推演很难建立直觉；开发者往往需要手动跑一长串访问序列才能对比两种策略。

Tool-Craft 现有工具集中没有任何缓存/替换算法类工具：`bloom-filter` 尚不存在（同轮另案 Idea），`bitmask-calculator` 是位运算，`regex-visualizer`、`json-*` 系列均不相关。活动池、completed.md、rejected.md 全文检索 LRU/LFU/缓存替换/cache eviction 均无命中（registry 中的 "cache" 字样仅出现在 PII 掩码等无关上下文）。

## 方案概述

构建纯前端缓存淘汰策略模拟器，核心能力：

1. **访问序列输入**：文本框输入键序列（如 `A B C A D B A`）或用随机生成器按 Zipf 偏态生成访问流，设定缓存容量 k。
2. **双策略并行回放**：同一条访问序列分别驱动 LRU（双向链表 + Map，O(1) get/put）与 LFU（频次桶 + 同频按 LRU 次序淘汰）两个缓存，逐步骤回放，每步展示命中/未命中、被淘汰的键、当前缓存内容。
3. **指标对比**：实时统计两种策略的命中次数、命中率、淘汰次数，并支持容量 k 从 1 到 N 扫描，绘制命中率随容量变化的双曲线。
4. **LFU 污染演示**：内置经典案例序列（某键前期高频访问后不再使用，长期占据缓存），一键载入并高亮计数滞留现象，可叠加"频次衰减"开关对比改进效果。

## 价值假设

- **面试与教学高频**：LRU/LFU 是 LeetCode 经典题（146、460）与系统设计缓存章节的核心，逐步回放比静态题解更易理解。
- **工程决策辅助**：可用真实业务抽样的 key 访问序列本地试算不同容量与策略的命中率，为 Redis 内存上限、本地缓存选型提供量化依据，数据不出浏览器。
- **补齐算法模拟类空白**：与现有 303 个工具无概念重叠，纯函数回放逻辑便于穷举测试。

## 目标用户

- 准备后端 / 系统设计面试的工程师与刷题学生；
- 设计本地缓存或评估 Redis maxmemory-policy 的后端开发；
- 讲解操作系统页面置换、数据库缓冲池淘汰策略的教师。

## 核心功能（MVP）

1. 访问序列文本输入 + Zipf 随机序列生成，容量 k 可配；
2. LRU 与 LFU 逐步同步回放，每步显示命中状态、淘汰键、缓存快照；
3. 命中率/淘汰数统计 + 容量扫描双曲线；
4. LFU 计数污染案例一键载入与衰减开关对照。

## 不做什么（边界）

- 不实现 ARC、W-TinyLFU、Clock、FIFO/Random 之外的更多策略（MVP 仅 LRU/LFU，避免范围膨胀）；
- 不做 TTL 过期、并发访问模拟与分布式一致性；
- 不接入真实 Redis 或任何外部服务；
- 不处理 value 载荷（只模拟键的存在性与元数据）。

## 技术可行性

- LRU 用 `Map` 插入序特性即可 O(1) 实现；LFU 用 `Map<key, freq>` + 频次桶 `Map<freq, Set<key>>`，均为标准原生数据结构，零依赖；
- 回放引擎设计为纯函数 `simulate(sequence, capacity, policy) → Step[]`，每一步缓存快照不可变更新，测试可直接断言完整步骤序列；
- 容量扫描曲线用现有工具同款的轻量 SVG/CSS 图表模式（参考 `color-palette` 等无依赖渲染方式）；
- 复杂度评估：**M**（两种策略 + 回放 + 扫描统计），符合 S–M 约束，主线程可处理万级访问序列。

## 验收标准

1. 经典序列 `A B C A D B A`、容量 2 下，LRU 逐步淘汰过程与教科书结果逐拍一致；
2. LFU 对同序列的频次计数与淘汰选择与 LeetCode 460 语义一致（同频按最久未用淘汰）；
3. 容量扫描 k=1..N 输出的命中率曲线单调不降；
4. 污染案例中 LFU 滞留键被明确高亮，开启衰减后该键可被淘汰；
5. 回放纯函数单测覆盖率 ≥90%，零网络请求、零新依赖。

## 风险与约束

- 万级序列全量保存快照有内存压力：默认保留全量步骤（教学场景通常 <1000 步），超长序列切换为仅保留统计 + 首尾快照；
- LFU 同频 tie-break 口径差异：固定采用同频 LRU 次序并在文档注明；
- Zipf 生成需确定性可复现：支持可选种子，基于 `mulberry32` 类轻量 PRNG（与 `random-data-generator` 同思路，无新依赖）。
