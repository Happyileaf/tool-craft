## 描述

在浏览器本地解析与生成 GNU gettext 消息目录文件：解析 `.po` / `.pot` 文本中的 msgid / msgstr、msgctxt、复数形式（msgid_plural / msgstr[n]）、多行续行字符串（`""` 拼接）、`#` 翻译者注释 / `#:` 行号引用 / `#,` 格式标志 / `#|` 旧值注释，以及头部 `msgid ""` 元数据块；输出为结构化 JSON（键含 msgid、msgstr、context、plurals、comments、references、flags），并支持从该 JSON 结构反向生成合法 PO 文本（含转义 `\"`、`\n`、`\\` 与多行折叠）。用于本地化流程中把翻译目录接入 Web/JSON 工具链或做批量检视。

现有配置转换工具（INI / .env / .properties / YAML / TOML 相关）均不覆盖 gettext 目录语法；`strings-json-converter` 面向 Apple `.strings`，格式与 PO 完全不同。PO 语法由 GNU gettext 手册确定，零依赖行状态机即可解析，固定样本可确定性断言，复杂度 M。

## 设计内容（进入 Claimed 前补全）

纯客户端单页工具，零网络、零新增依赖；PO 解析/序列化收敛为可单测纯函数 `utils/po.ts`（行状态机），UI 负责方向切换、双编辑器与错误/结果渲染。

- **输入**：PO/POT → JSON 方向粘贴 gettext 目录文本；JSON → PO 方向粘贴顶层键值映射 JSON。
- **核心处理**：① 行状态机识别 msgctxt、msgid、msgid_plural、msgstr[n] 关键字与相邻引号续行，拼接跨行字面量；② 处理 `\n`、`\t`、`\"`、`\\` 等 C 风格转义与 # 系列注释（# / #. / #: / #, / #|）；③ 带 msgctxt 条目以显式常量 `MSGCTXT_SEPARATOR='\u0001'`（SOH）连接 context 与 msgid 作 JSON 键；④ 复数条目映射字符串数组，反向生成自动补 msgid_plural；⑤ 无法识别的行抛出带原文的错误。
- **输出**：结构化 JSON（含 header、单复数、注释）或合法 PO 文本；错误时展示红色告警与出错行。
- **边界**：空文件、顶层非对象 JSON、未知关键字、损坏转义均明确报错；固定样本做双向往返断言。
