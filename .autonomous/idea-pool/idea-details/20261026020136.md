## 描述

提供经纬度坐标在 WGS-84（GPS/国际标准）、GCJ-02（国测局/高德、腾讯火星坐标）、BD-09（百度坐标）三种坐标系之间的双向批量转换，并对中国境外坐标按通行实现做不偏移处理。面向国内地图应用、LBS 数据对齐与多平台数据融合的开发刚需。转换基于固定椭球参数的纯数学偏移/纠偏公式（含国境外判断），本地确定性计算、零网络依赖、可用固定坐标点做可验证验收。注意：本工具解决的是坐标**基准/加密体系转换**，与池中已有的「地理坐标格式转换（十进制 ↔ 度分秒）」（仅表示格式转换）是不同问题，不构成重复。

## 设计内容（进入 Claimed 前补全）

- **工具 slug**：`coordinate-system-converter`
- **分类 / 图标**：`ToolCategoryEnum.DEV_CODE`（面向地图 / LBS 研发的调试辅助）；图标 `Code`
- **查重结论**：registry 与池内无任何坐标基准转换工具；池内 20261017220043「地理坐标格式转换（十进制 ↔ 度分秒）」仅做同一点位的表示格式换算，不涉及 GCJ-02 加密偏移；geohash-codec（本轮另一入选）是坐标 ↔ 空间索引串编码，亦不重叠；rejected.md 无同类归档。
- **文件结构**（四件套，零新依赖）：
  - `constants.ts`：椭球参数 `A = 6378245.0`、`EE = 0.00669342162296594323`、`X_PI = Math.PI * 3000 / 180`；`CoordinateSystemEnum`（wgs84/gcj02/bd09）与 `SYSTEM_OPTIONS`（WGS-84 GPS 国际 / GCJ-02 火星坐标 / BD-09 百度）；`DEFAULT_SAMPLE = '116.404,39.915\n121.4737,31.2304'`（北京天安门、上海人民广场）
  - `utils/coordinate.ts`：纯函数
    - `outOfChina(lng, lat)`：按通行矩形（经度 72.004–137.8347、纬度 0.8293–55.8271）判断，境外不偏移
    - `transformLat(x, y)` / `transformLng(x, y)`：标准偏移多项式
    - `wgs84ToGcj02(lng, lat)`：国境外原样返回；境内按标准 delta 公式
    - `gcj02ToWgs84(lng, lat)`：通行减法近似（delta 反算）
    - `gcj02ToBd09(lng, lat)`：`z = sqrt(x²+y²) + 0.00002 sin(y·X_PI)`，theta = atan2(y,x) + 0.000003 cos(x·X_PI)`
    - `bd09ToGcj02(bdLng, bdLat)`：上述反解
    - `convert(lng, lat, from, to)`：组合上述基础转换（WGS↔BD 经 GCJ 中转）
    - `convertBatch(text, from, to)`：每行「经度,纬度」解析，空行跳过，返回每行 `{ source, ok, lng?, lat?, outOfChina?, error? }`
  - `index.tsx`：源坐标系 / 目标坐标系两个 Radio 或 Select（同系时原样输出并提示）、输入 TextArea（每行 `经度,纬度`）、结果 Table（原值、转换后经纬度、是否境外未偏移、错误）+ 只读 TextArea（可复制的批量结果）；载入示例 / 清空 / 复制；非法行内联提示不阻塞整批
  - `index.module.css`：container/toolbar/result/hint 等
- **注册**：`registry.ts` 追加双语 ToolMeta（DEV_CODE / Code / isNew / MAINTHREAD / defaultSampleInput 为两行中国坐标）；`loaders.ts` 追加懒加载；FAQ 至少含「三种坐标系分别是什么、各家地图用哪种」「为何境外坐标不偏移」「反向转换为何是近似值（GCJ-02 非官方可逆）」
- **边界**：输入顺序为「经度,纬度」（lng,lat，与 GeoJSON / 高德一致），越界经纬度报错；GCJ→WGS 采用通行减法近似（非官方逆算法），页面注明误差量级；不做批量文件上传 / 地图可视化；仅十进制经纬度
