## 描述

CAN（Controller Area Network）广泛用于汽车与工业总线，嵌入式工程师在配置控制器、分析报文时需要：按帧字段（SOF、仲裁场、控制场、数据场、CRC、ACK、EOF）推算帧长度与位填充后的实际位数，计算 CRC-15 校验序列，以及由 CAN 时钟、波特率预分频器（BRP）与时间段（TSEG1/TSEG2、SJW）反算波特率和采样点。现有工具集覆盖以太网/IP/TCP/UDP/ARP/RTP/Modbus 等协议，唯独缺少车载/工业 CAN 这一支。本工具在浏览器本地完成 CAN 2.0A/B 经典帧的字段级计算与位时序换算，全部为确定性位运算与整数算术、零依赖。

## 设计内容（进入 Claimed 前补全）

**功能范围**：① 帧长度计算：输入帧格式（标准 11 位 ID / 扩展 29 位 ID）、DLC（0–8 字节）、IDE/RTR 标志，输出未填充的理论位数（帧各固定字段 + 数据位）；② 位填充计数：对给定 ID + 数据按 CAN「连续 5 个同电平后插入 1 个相反位」规则模拟 SOF→CRC 序列（含 stuff bit count），给出填充后总位数与在给定波特率下的线上传输耗时（µs）；③ CRC-15：按 ISO 11898-1 多项式 x¹⁵+x¹⁴+x¹⁰+x⁸+x⁷+x⁴+x³+1（0xC599）对帧的受保护位序列计算 15 位 CRC 与 CRC 界定符；④ 位时序 / 波特率：输入 CAN 外设时钟 f_clk、BRP、TSEG1、TSEG2（以 tq 计）、SJW，计算位时间 tq 数、每位时间、波特率、采样点百分比，并做采样点推荐区间（常见 75%–87.5%）校验与正向反算互验。

**核心交互**：分区卡片——「帧与位填充」区（帧格式/RTR/DLC/ID/数据 hex 输入，输出理论位、填充位、总位、耗时）、「CRC-15」区（hex 序列输入，输出 15 位 CRC 的 hex 与二进制）、「位时序」区（时钟/BRP/时间段数字输入，输出波特率与采样点）；示例帧一键填充、结果一键复制、错误以 Result 面板呈现。

**输入输出**：输入为帧字段、数据字节 hex、时钟频率与位时序参数；输出为理论/填充后位数、stuff bit 数、传输耗时、CRC-15 值、tq 数、波特率（bit/s）、采样点百分比与合规结论。

**边界情况**：DLC > 8（经典帧不支持 CAN FD 长度）→ 报错并提示本工具仅 CAN 2.0；标准帧 ID > 0x7FF、扩展帧 ID > 0x1FFFFFFF → 报错；数据 hex 字节数与 DLC 不符 → 报错；BRP/TSEG 取 0 或越界 → 报错；f_clk 不能被整除时给出实际波特率与误差百分比；空数据（DLC=0）仍正确计算 CRC 与固定字段位；CRC 只覆盖 SOF 至数据场（含 stuff 前的原始位流规则），不含 CRC 场本身。

## 验收标准（进入 Claimed 前补全，必须可验证）

- [ ] 标准数据帧、DLC=0、ID=0x000：理论位数 = 47（SOF 1 + 11 ID + RTR/IDE/r0 共 3 + DLC 4 + CRC 15 + CRC 界定符 1 + ACK 槽 1 + ACK 界定符 1 + EOF 7 + 帧间不计时），字段拆解可逐项相加核对
- [ ] 扩展数据帧相对标准帧在仲裁/控制场多出 18 位（SRR/IDE + 18 位扩展 ID 等），同 DLC 下理论位数 = 标准帧 + 20（按 ISO 11898-1 字段表固定断言）
- [ ] CRC-15：对全 0 的最短受保护位序列与一个给定非零数据帧，分别输出与独立参考实现一致的固定 15 位值（实现时以 ISO 11898-1 附录示例向量锁定，断言 hex 与二进制）
- [ ] 位填充：构造会产生连续 5 同电平的 ID/数据（如全 0x00 数据），stuff bit 计数 > 0 且填充后总位 = 理论位 + stuff 数；给定 500 kbit/s 时总耗时（µs）= 总位数 / 500000 × 1e6
- [ ] 位时序：f_clk=48 MHz、BRP=6、TSEG1=11、TSEG2=4 → tq 数 = 1+11+4=16，每位 16×(6/48MHz)=2 µs，波特率 = 500000 bit/s，采样点 = (1+11)/16 = 75%，落在推荐区间
- [ ] DLC=9、标准 ID=0x800、BRP=0、数据字节数与 DLC 不符等非法输入分别返回明确错误，不抛到页面
