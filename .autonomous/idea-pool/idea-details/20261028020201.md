## 描述

在文本 / 字节与 Base62（字母表 `0-9A-Za-z` 共 62 个字符）之间双向编解码，补齐 Tool-Craft 已有的 Base16/32/45/58/64/85 编码家族中缺失的 Base62。Base62 因字符集 URL-safe、肉眼无歧义（不含 `0O`/`1l` 之外的符号问题由具体字母表处理），被广泛用于短链 token、URL slug、数据库短 ID 与二进制数据的可打印表示；工具需支持常见的两种字母表顺序（GMP 十进制风格 `0-9A-Za-z` 与替代风格 `0-9a-zA-Z`），并明确区分两种主流编码语义：把输入先转为大整数再按 62 进制表示（整数模式，空输入与前导零处理需明确），以及把字节按 62 进制转换（字节模式，往返需保留前导零字节，参照 Base58 的做法）。非法字符与解码失败给出明确提示。全部为本地确定性运算，基于 BigInt 实现，纯函数，零新增依赖。与现有 base58-codec（含 Base58Check 校验和及 Bitcoin/Flickr/Ripple 字母表）、number-base-converter（定长进制数值与位运算）均不重叠：前者面向 Base58 体系及校验和地址场景，后者面向固定进制数值展示，本工具专门覆盖通用 Base62 文本/字节编解码。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：Base62 双向编解码，工具 slug 拟为 `base62-codec`。
- **字母表**：支持两种顺序切换——GMP 风格 `0-9A-Za-z` 与替代风格 `0-9a-zA-Z`。
- **整数模式**：输入按十进制/十六进制文本解析为 BigInt 后按 62 进制表示；`0` 编码为 `"0"`；解码输出大整数文本。
- **字节模式**：把 UTF-8 字节串先按前导零字节计数再转 BigInt 做 Base62 表示（参照 Base58 做法），解码时还原前导零字节，保证任意字节串往返一致。
- **核心交互**：文本输入 + 模式（整数/字节）+ 字母表切换，实时双向编解码；非法字符 / 解码失败给出明确错误。
- **输入输出**：核心编解码为纯函数（BigInt 实现），不触碰 DOM / React，零新增依赖。
- **边界情况**：空输入、`0`、含前导零字节的二进制数据、非法字符。

## 验收标准（进入 Claimed 前补全，必须可验证）

- [ ] 整数模式：已知大整数 / 十六进制输入经 Base62 编码后与公认结果一致（如十进制 `0`、`256`、大整数），并可往返还原
- [ ] 字节模式：任意字节串（含前导零字节、空输入、二进制随机数据）编码后解码完全一致，前导零不丢失
