## 描述

解析 HTTP 缓存相关响应头并计算资源在各时刻的缓存状态：逐 token 解析 `Cache-Control`（`public` / `private` / `no-cache` / `no-store` / `max-age` / `s-maxage` / `must-revalidate` / `proxy-revalidate` / `immutable` / `stale-while-revalidate` / `stale-if-error` / `no-transform` 等，含未知指令与冲突指令提示），结合 `Age`、`Expires`、`Date`、请求侧 `Cache-Control: max-age=0/no-cache` 与协商缓存头（`ETag` / `Last-Modified`），按 RFC 9111 计算新鲜度寿命（freshness lifetime）、当前年龄（corrected age）、新鲜/过期/必须重新验证结论，以及给定「当前时间」下的剩余新鲜秒数；反向模式可根据目标缓存时长生成推荐响应头组合。典型场景：调试 CDN / 浏览器缓存行为、设计 API 缓存策略。纯本地计算、确定性输出、零依赖，可用 RFC 9111 附录算例做固定向量验收。边界：在池「原始 HTTP 报文解析器」（20261026200350）对 Cache-Control 仅做指令层面的人类可读展开，不含 Age 校正与新鲜度寿命的数值计算；`content-negotiation-parser` 只处理 Accept 系列请求头、`security-txt-generator` 等生成器不涉及缓存语义——本工具是面向缓存策略的独立语义计算器，不构成重复。

## 设计内容（进入 Claimed 前补全）

- 功能范围：解析响应侧 `Cache-Control`（public/private/no-cache/no-store/max-age/s-maxage/must-revalidate/proxy-revalidate/immutable/stale-while-revalidate/stale-if-error/no-transform 及未知指令标记），结合 `Age`、`Date`、`Expires` 与请求侧 `Cache-Control`，按 RFC 9111 计算 freshness lifetime、corrected current age、fresh/stale/revalidate 结论与剩余新鲜秒数。
- 新鲜度寿命优先级：显式 `s-maxage`（共享缓存）> `max-age` > `Expires − Date` > 缺省 heuristic 提示；当前年龄取 ` apparent_age` 与 `Age` 的 corrected age 算法。
- 核心交互：响应头文本框（多行 `Key: Value`）+ 当前时间选择（默认本机时间）+ 结论卡片（寿命、年龄、剩余秒数、状态徽标、冲突/未知指令提示）+ 协商缓存头（ETag/Last-Modified）存在性提示。
- 纯函数：指令 token 解析、年龄计算、状态判定全部置于 `utils/`，时间以可注入 `now` 保证单测确定性。
- 边界：`no-store` 直接判定不可缓存并短路；冲突指令（如 no-cache 同时 max-age）逐条提示；非法 Age/日期返回解析错误；反向生成头组合不纳入本轮 MVP。

## 验收标准（进入 Claimed 前补全，必须可验证）
