## 描述

解析 HTTP 缓存相关响应头并计算资源在各时刻的缓存状态：逐 token 解析 `Cache-Control`（`public` / `private` / `no-cache` / `no-store` / `max-age` / `s-maxage` / `must-revalidate` / `proxy-revalidate` / `immutable` / `stale-while-revalidate` / `stale-if-error` / `no-transform` 等，含未知指令与冲突指令提示），结合 `Age`、`Expires`、`Date`、请求侧 `Cache-Control: max-age=0/no-cache` 与协商缓存头（`ETag` / `Last-Modified`），按 RFC 9111 计算新鲜度寿命（freshness lifetime）、当前年龄（corrected age）、新鲜/过期/必须重新验证结论，以及给定「当前时间」下的剩余新鲜秒数；反向模式可根据目标缓存时长生成推荐响应头组合。典型场景：调试 CDN / 浏览器缓存行为、设计 API 缓存策略。纯本地计算、确定性输出、零依赖，可用 RFC 9111 附录算例做固定向量验收。边界：在池「原始 HTTP 报文解析器」（20261026200350）对 Cache-Control 仅做指令层面的人类可读展开，不含 Age 校正与新鲜度寿命的数值计算；`content-negotiation-parser` 只处理 Accept 系列请求头、`security-txt-generator` 等生成器不涉及缓存语义——本工具是面向缓存策略的独立语义计算器，不构成重复。
