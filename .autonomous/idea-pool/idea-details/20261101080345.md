## 描述

解析 HTTP 内容协商请求头（`Accept`、`Accept-Language`、`Accept-Encoding`、`Accept-Charset`），按 RFC 9110 §12.5 规则展开媒体范围/标签的通配匹配、解析每个条目的 `q` 质量因子（缺省为 1），并按「质量因子降序、同质量时具体度优先（类型/子类型具体程度、标签长度、通配符 * 排末位）」输出服务端应选择的表示排序，帮助后端开发者调试与理解内容协商结果。纯字符串解析与排序的确定性算法，纯函数可单测、固定向量可验收，零新增依赖。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：解析 Accept / Accept-Language / Accept-Encoding / Accept-Charset 四类内容协商请求头，工具 slug 拟为 `content-negotiation-parser`。
- **核心算法**：按逗号拆分条目，分号提取 `q` 质量因子（缺省 1，范围 0–1，非法 q 忽略整个参数或按规范处理）；媒体范围解析 type/subtype 与参数（如 `level`），语言标签按前缀匹配。
- **排序规则（RFC 9110 §12.5）**：先按 q 降序；同 q 时具体度优先——类型/子类型非通配比 `*/*` 具体、参数更多更优先；语言标签更长更具体；`*` 排末位。
- **核心交互**：上方选择头类型，文本框粘贴请求头值；下方实时输出排序后的表示列表（名称、q 值、具体度说明）与服务端应首选的表示；支持一次粘贴多组头。
- **边界情况**：空串、非法 q（>1、负数、非数字）、重复条目、`*/*`、`zh;q=0.9, zh-CN;q=1` 等给出确定性结果；纯函数不触碰 DOM / React。
