## 描述

面向智能楼宇 / 暖通空调（HVAC）与物联网集成调试场景，对 BACnet/IP（ANSI/ASHRAE 135，UDP 端口 47808）报文做本地双向编解码，按三层结构逐层拆解。链路层 BVLC（BACnet Virtual Link Control）：解析 BVLC Type（0x81）、Function（如 0x0A Original-Unicast-NPDU、0x0B Original-Broadcast、0x05 Forwarded-NPDU、0x04 Forwarded-NAK 等）与长度字段，校验声明长度与实际字节数一致性，Forwarded 帧额外拆解原始发送方 IP:Port。网络层 NPDU：解析 Version（固定 0x01）、控制字节各位（网络层消息标志、目的/源网络指示、期望应答、优先级 2 bit），按标志位条件拆解 DNET/DLEN/DADR、SNET/SLEN/SADR、Hop Count 与 Network Layer Message Type。应用层 APDU 限定常用服务子集：Who-Is / I-Am（含设备 Object Identifier、最大 APDU 长度、分段能力、Vendor ID）、Read-Property / Read-Property-ACK（对象类型与实例号、属性 ID、Tag 类型/长度/值的应用标签解码，含无符号、有符号、枚举、布尔、实数字节序、字符串、对象标识符等原始标签类型），并给出 PDU 类型/标志/最大分段/调用 Invoke ID 的位级释义。构造方向按服务表单生成合法 BACnet/IP 十六进制报文（自动拼装 BVLC 长度、NPDU 控制位与 APDU 标签 TLV）。范围明确限定上述常用服务与原始应用标签，不覆盖写服务、COV 订阅、分段重组、BACnet MS/TP 串口链路与全部对象属性表，保证单一可验收边界。全部为确定性的 TLV 标签编解码、字节序转换、长度与位域运算，零新增依赖、纯本地计算，可用抓包固定向量做解析、构造往返与错误注入（BVLC 长度不符、保留 Version、非法 Tag Number/Length、地址长度越界）验收。现有工业协议工具 `modbus-frame-codec`（已实现）与活动池中的 CAN 2.0 帧工具面向寄存器/功能码与总线帧位时序，字段体系完全不同；网络协议 codec（DNS/ARP/DHCP/RTP/TCP/UDP）亦无 BACnet 的 BVLC/NPDU/APDU 三层与应用标签 TLV 语义，本工具非其能力子集。四源查重对「BACnet / BVLC / 楼宇 / 自控 / 智能建筑 / building / IoT 报文」全文检索，活动池、completed.md、rejected.md 与工具目录均无相同或高度相似 Idea，符合红线。
