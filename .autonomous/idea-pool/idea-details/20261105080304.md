## 描述

在浏览器本地对 Markdown 文档做静态链接体检（不发起任何网络请求，符合 local-first 约束）：(1) 提取全部行内链接 `[text](url)`、引用式链接 `[text][ref]` 与紧凑引用 `[ref][]`、引用定义 `[ref]: url "title"`、自动链接与裸 URL；(2) 检查引用式标签是否有未定义引用（used but not defined）、定义了但从未使用的引用（defined but unused）、同一标签重复定义；(3) 对文档内 `#anchor` 相对锚点，按 GitHub 风格 slug 规则（小写、空格转连字符、去除标点）与文中实际标题比对，报告失效锚点；(4) 汇总外链/相对链接/邮件链接/锚点链接分类计数，按行号列出问题清单。

现有 `markdown-toc-generator` 只从标题生成目录（含锚点生成），`markdown-preview` 只做渲染，`pattern-extractor` 只做通用模式抽取，均不做引用一致性与锚点有效性校验。解析规则由 CommonMark 链接语法与 GitHub slug 规则确定，零依赖纯函数可用固定文档样本做确定性断言，复杂度 M。

## 设计内容（进入 Claimed 前补全）

**实现载体**：`apps/web/src/tools/markdown-link-checker/`（`index.tsx` + `checker.ts` 纯函数 + `__tests__/checker.test.ts`），分类 `Text`，零依赖、零网络请求（明确不做外链可达性探测）、主线程。

**功能范围**：
1. 逐行扫描（保留行号），用一组确定性正则/状态机提取：行内链接 `[text](url "title")`、引用式 `[text][ref]`、紧凑引用 `[ref][]`、简写 `[ref]`（当存在同名定义时）、引用定义 `[ref]: url "title"`、自动链接 `<http://...>`/`<mail@x.com>`、裸 URL（`http(s)://` 开头）。跳过围栏代码块（``` ）与行内代码 `` ` `` 中的内容，避免误报。
2. 引用一致性检查（标签大小写不敏感，遵循 CommonMark 折叠规则）：未定义引用（used-but-not-defined）、未使用定义（defined-but-unused）、重复定义（同标签多次定义，报首次之后的行号）。
3. 锚点校验：收集 ATX 标题（`#`–`######`）与 Setext 标题，按 GitHub slug 规则生成锚点（转小写、去除非字母数字/连字符/下划线/中文等字符、空格转 `-`、连续空格单连字符）；对 `#xxx` 及 `relative.md#xxx` 中的纯页内锚点比对，缺失则报失效锚点；仅 `#` 视为页首合法。
4. 链接分类计数：external（http/https 自动/裸链）、relative（相对路径，含 `.md`）、anchor（`#` 开头）、mail（`mailto:` / `<mail>`）、其他；按行号输出问题清单（级别 error/warning/info），顶部汇总卡片；提供 2 组含各类问题的示例文档。

**输入输出**：输入 Markdown 文本；输出 `{ links: [{line,type,text,url,ref?}][], definitions, headings: {line,slug}[], issues: [{line,severity,code,message}][], counts: {external,relative,anchor,mail} }`。

**边界情况**：空文档、围栏/行内代码中的类链接文本不提取、引用标签大小写折叠、重复定义、图片 `![alt](...)` 作为链接统计但标注 image、标题含标点/emoji/中文的 slug、无标题文档中的锚点全部失效、裸 URL 边界标点截断、转义字符 `\]`。
