## 描述

按 RFC 5321/5322 语法对邮箱地址做本地校验与结构化拆解：校验整体合法性，拆分 local-part 与 domain，识别点号引号、注释、IPv4/IPv6 字面量域、IDN 国际化域名（punycode 标注）等形态，并逐条给出非法原因。解决开发者表单校验、数据清洗时只能靠简单正则、无法解释失败原因的问题。

## 设计内容（进入 Claimed 前补全）

**实现载体**：`apps/web/src/tools/email-syntax-validator/` 纯前端工具（`index.tsx` + `validator.ts` 纯函数 + `__tests__/validator.test.ts`），分类 `Developer`，零第三方依赖、零网络请求、主线程运行。

**功能范围**：
1. 输入单个邮箱地址（去首尾空白），输出整体合法/非法结论与逐条原因列表。
2. 结构化拆解：local-part、domain；标注 local-part 形态（dot-atom / quoted-string）、domain 形态（domain 字面量 / IPv4 / IPv6 字面量）、是否含 IDN（非 ASCII 字符提示需 punycode 编码，仅标注不做转换）。
3. 规则校验（确定性字符级检查，不追求 RFC 5322 全量边角语法，覆盖主流实践）：
   - 必须恰好含 1 个未被引号包裹的 `@`；local-part/domain 非空。
   - local-part：长度 ≤64；dot-atom 下允许字母数字与 `!#$%&'*+-/=?^_`{|}~.`，点号不能位于首尾、不能连续；quoted-string（双引号包裹）内允许空格与点号等，引号需成对、转义正确。
   - domain：普通域按标签拆分，标签 1–63 字符、整体 ≤255，仅字母数字连字符、连字符不居首尾、点号不连续/不居首尾；支持 `[1.2.3.4]` IPv4 字面量（校验四段 0–255）与 `[IPv6:...]` 字面量（基础十六进制/冒号格式校验）。
   - 总长度 ≤254（RFC 5321 实际传输上限）。
4. 界面：文本输入 + 校验按钮（实时/按钮触发皆可），结果区展示状态徽标、解析字段卡片、原因清单；提供 3–5 个示例一键填充。

**输入输出**：输入字符串；输出 `{ valid: boolean, reasons: string[], parts: { localPart, domain, localType, domainType, isIdn } | null }`。

**边界情况**：空输入、多个 `@`、缺 local/domain、连续点、点号居首尾、超长、非法字符、域标签连字符位置、IPv4 越界（256）、非 ASCII 域（IDN 提示）、引号未闭合。

## 验收标准（进入 Claimed 前补全，必须可验证）

- [ ] 合法地址（`user@example.com`、`a.b+c@sub.example.co`、`"john doe"@example.com`）判定 valid 且正确拆分 local/domain 与形态。
- [ ] 非法地址逐条给出原因：`a..b@example.com`（连续点）、`.a@example.com`（点号居首）、`a@b`（单标签域允许，需明确策略——本工具允许单标签域但标注 warning）、`a@.com`（空标签）、`ab@[256.1.1.1]`（IPv4 越界）、`a b@example.com`（未引号空格）、无 `@`、两个 `@`。
- [ ] 含非 ASCII 域（`用户@例子.中国`）标注 IDN/punycode 提示；local-part 超长（65 字符）与总长超 254 被拒。
- [ ] 纯函数单测覆盖上述全部向量，`pnpm test` 通过；`lint`/`typecheck`/`build` 通过。
