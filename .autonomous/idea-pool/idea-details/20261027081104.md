## 描述

提供 RFC 7386 定义的 JSON Merge Patch 能力：在两个 JSON 文档之间生成最小 merge patch（null 表示删除键），或将给定 patch 应用到原文档输出结果，并高亮变更。面向 API 开发与调试中按 merge patch 语义做部分更新的场景。与已有 JSON 工具不重叠：`json-formatter` 只做格式化校验、`json-flatten` 做点路径扁平化、JSON 结构化差异对比只做展示，本工具产出符合 RFC 7396 语义、可直接发送给服务端的 patch 文档。

## 设计内容（进入 Claimed 前补全）

- **工具 slug**：`json-merge-patch`
- **分类 / 图标**：`ToolCategoryEnum.DATA_JSON`；图标 `Braces`
- **查重结论**：`json-formatter` 仅格式化 / 校验、`json-flatten` 做点路径扁平化、`json-ndjson-converter` 做行式 JSON 转换、`json-to-typescript` / `yaml-to-json` 均无 patch 语义；池内「JSON 结构化差异对比」只做展示不产出可发送的 merge patch 文档；rejected.md 无同类归档。不构成重复。
- **文件结构**（四件套，零新依赖）：
  - `constants.ts`：`ModeEnum`（apply 应用补丁 / generate 生成补丁）与 `MODE_OPTIONS`、`DEFAULT_ORIGINAL`（RFC 7386 示例原文档）、`DEFAULT_PATCH`（RFC 官方补丁示例）、`DEFAULT_TARGET`
  - `utils/mergePatch.ts`：纯函数
    - `parseJson(text)`：`JSON.parse` 包装，错误时抛出含行 / 列 / 原因的 `{ message, line, column }`
    - `applyPatch(target, patch)`：严格按 RFC 7386 §2 递归——非对象 patch 整体替换；对象 patch 逐键：值为 null 删除键；键不存在则新增；双方均为普通对象则递归合并；数组整体替换
    - `generatePatch(source, target)`：按 RFC 7396 语义生成最小补丁——递归比较普通对象：目标缺失键 → `null`；值不同 → 双方均为普通对象递归，否则取目标值；数组 / 标量直接取目标值；满足 `applyPatch(source, generatePatch(source, target))` 深等于 target
    - `isPlainObject(value)`：排除 null / 数组
  - `index.tsx`：模式 Radio（应用补丁 / 生成补丁）；应用模式双栏（原文档 / patch），结果栏展示应用结果 JSON（2 空格缩进），错误行内 Alert 定位行号；生成模式双栏（原文档 / 目标文档），结果栏展示补丁 JSON 并支持一键复制；载入示例 / 清空 / 复制
  - `index.module.css`：container/toolbar/editor/result/error 等
- **注册**：`registry.ts` 追加双语 ToolMeta（DATA_JSON / Braces / isNew / MAINTHREAD / defaultSampleInput 为 RFC 示例 JSON）；`loaders.ts` 追加懒加载；FAQ 至少含「null 在 merge patch 中的含义」「数组为何整体替换而非合并」「merge patch 无法表达的操作（与 JSON Patch RFC 6902 区别）」
- **边界**：仅处理 JSON 文档；patch 为数组 / 标量时按 RFC 整体替换目标；不支持 JSON Patch（RFC 6902）的路径操作；不做注释 / 尾随逗号容错
