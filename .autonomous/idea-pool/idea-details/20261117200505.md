## 描述

输入 Solidity 风格的函数或事件签名（如 `transfer(address,uint256)`），按 Ethereum ABI 规范计算 keccak-256 摘要：函数取摘要前 4 字节（8 个十六进制字符）作为 selector（含 `0x` 前缀），事件取完整 32 字节摘要作为 Topic0。支持从完整 ABI JSON（function / event 条目数组）批量提取规范签名（canonical signature，tuple 展开、无空格、无参数名、storage 关键字剔除）并一次性产出全部 selector / topic0 表格，可反向粘贴 4 字节 selector 在本次输入集合内匹配签名。keccak-256 用零依赖本地实现（与现有 rlp-codec / eip55 工具链同源思路，不引新依赖），私钥等敏感输入不参与，仅处理公开签名。

## 设计内容（进入 Claimed 前补全）

功能范围：单页双模式。① 签名模式：文本输入单条规范签名，选择 function / event，输出 keccak-256 全摘要、函数 selector（前 4 字节）或事件 Topic0；② ABI JSON 模式：粘贴 ABI 数组，过滤 `type` 为 function / event / receive / fallback 的条目，对 function 与 event 生成 canonical signature 并批量计算，receive / fallback 给出特殊 selector 说明（receive/fallback 无 selector 或固定空）。结果表格含签名、类型、selector / topic0、一键复制。

核心交互：模式切换、签名输入框、ABI JSON 输入框、结果卡片与表格、selector 反向匹配输入框、错误提示（非法 JSON、tuple 括号不匹配、不支持的类型名）；计算在主线程同步完成（单条 <1ms，批量 ABI 通常数十条）。

输入输出：输入为签名字符串或 ABI JSON；输出为 `{ canonicalSignature, hash32, selector?, topic0? }` 结构与可复制十六进制字符串。

边界情况：签名规范化需剔除参数名与多余空格（`transfer(address from, uint256 amount)` → `transfer(address,uint256)`）；tuple 类型递归展开为 `(type1,type2)`；不合法的 UTF-8 / 空签名 / 仅函数名无括号给出明确错误；keccak 输出统一小写 `0x` 前缀；ABI 中 constructor 不计 selector，error 类型按函数同规则计算（Solidity 自定义 error 同样使用 4 字节 selector）并在类型列标注。
