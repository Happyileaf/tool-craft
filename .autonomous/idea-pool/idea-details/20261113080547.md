## 描述

针对 HTTP 响应头 `Content-Disposition`（如 `attachment; filename="report.pdf"; filename*=UTF-8''%E6%8A%A5%E5%91%8A.pdf`）做解析与构造：识别 disposition 类型（`attachment` / `inline` / 扩展 token），拆解普通 `filename` 与带字符集/语言的扩展参数 `filename*`（RFC 5987/8187 的 `ext-value = charset"'[lang]'"value-chars`，百分号编码 + UTF-8 解码），并按 RFC 6266 §4.2 的优先级给出最终应采用的文件名；反向支持由一个含非 ASCII 字符的文件名生成合规的 `filename`（ASCII 降级）+ `filename*`（UTF-8 编码）双头值。现有 `multipart-form-builder` 仅在请求体拼装中间接生成该字段，没有面向响应头的独立解析/构造与 `filename*` 编解码能力；`url-encoder` 只做通用百分号编码、不处理 ext-value 的 charset/lang 结构与头参数语法。纯本地确定性计算、零新增依赖。

## 设计内容（进入 Claimed 前补全）

- **功能范围**：实现 RFC 6266 响应头字段的解析与构造，并完整支持 RFC 5987/8187 ext-value，工具 slug 拟为 `content-disposition-codec`。
- **核心算法**：
  - 解析：按 RFC 6266 §4.1 词法切分 disposition-type 与参数列表，正确处理引号字符串、空白、分号分隔；对 `filename` 与 `filename*` 分别提取，对后者按 `charset'lang'pct-encoded` 三段拆分并做 UTF-8 百分号解码。
  - 文件名决策：按 §4.2 规则——存在合法 `filename*` 时优先采用，否则回退 `filename`，两者都缺则无文件名。
  - 构造：由 Unicode 文件名生成 `filename*=UTF-8''<pct-encoded>`，并同时给出仅含 ASCII 的 `filename="..."` 降级值（非 ASCII 以 `%xx` 或替换字符处理），输出完整头值。
- **核心交互**：方向切换（解析 / 构造）、参数键值表格、最终文件名高亮、charset/lang 展示、复制 / 载入示例。
- **输入输出**：纯函数 `utils/contentDisposition.ts`（解析 + ext-value 编解码），不触碰 DOM / React。
- **边界情况**：空输入返回空；缺类型、重复参数、畸形 ext-value、未知 charset、未闭合引号等返回明确错误而非抛异常；仅处理响应头语义（不实现 multipart body 边界）；不做网络请求、不持久化输入。

## 参考资料

- RFC 6266（Use of the Content-Disposition Header Field，§4.1 语法、§4.2 文件名解析算法）；RFC 5987 / 被其更新的 RFC 8187（ext-value 编码）。
